Grammar surface

Syntax And Symbols

Key lexer tokens, comment formatting, blocks, OOP declarations, HTML views, and routes.

Comments

(( Any documentation comment or note. ))

Comments are delimited with double parentheses and are completely ignored by the compiler.

Class Declarations

User Model subclass
  users table
  email field
end

Declaration shape remains postfix: the declaration name is specified first, the declaration operator last.

Argument Lists

( ctx -> Response ) "index" [
  ctx get "home/index" swap view
] !method

Parentheses create optional input/output metadata bindings for functions and class methods.

Blocks

[ self .email get ]

Square brackets define first-class bytecode block values. Use the call word to run them.

Conditionals

result dup ok? if
  value
else
  error .message get
end

Postfix conditional execution flow: the test condition is evaluated on the stack prior to hitting if.

Members

user .email get
"ada@example.com" user .email set

Dot words push member selectors to load/store variables, or dispatch methods when called directly.

Templates

<strong>{ user get .name get }</strong>
<small>{ 20 22 + }</small>

HTML views support { ... } blocks. Each runs Ricochet and must output exactly one scalar value.

Routes

GET "/" HomeController "index" route
POST "/users" UserController "create" route

Route definitions are parsed line-by-line using quoted URL patterns and action method mappings.

OOP Examples

How OOP works under the hood in a concatenative environment.

Class-First Model File

app/Models/User.rco

Standard convention: write one class declaration per file, matching the class's name.

(( app/Models/User.rco ))
User Model subclass
  users table
  id field
  email field
  name field

  "displayName" [
    self .name get
    dup nil? if
      drop self .email get
    else
      return
    end
  ] !method
end

Toolchain commands

CLI Reference

Comprehensive list of commands available in the Ricochet command-line interface.

rco new <path>
Create a new MVC Ricochet application structure.
rco check [path]
Perform compile-time checks on script files or web applications.
rco repl [--debug]
Launch an interactive terminal REPL and print the stack trace after each evaluation.
rco run [--debug] [--step] [--breakpoint LINE] <path>
Compile and execute a Ricochet source script file.
rco build [path]
Compile and bundle source code into a bytecode file (defaults to `build/app.rcob`).
rco serve [--debug] [--watch]
Spin up a local web server for the current MVC project.
rco test [--debug] [path]
Locate and execute test cases defined inside standard `tests` folders.
Current truth, not future promises

Known Current Limits

The bounds of the v1.0.0 draft specification. Be aware of these rules in your application code.

  • Integer values are stored as 64-bit signed integers (i64); the lexer currently parses non-negative decimal literals.
  • Addition exists; subtraction, multiplication, division, loops, async, packages, and AI package words are not implemented yet.
  • Result types cannot be used directly as conditions. You must check with ok?, then extract with value or error.
  • Top-level method declarations are rejected; methods must reside in a class declaration or be installed via !method.
  • Active Record targets existing PostgreSQL schemas in v1. Schema migrations are a later branch.
  • Template expressions must leave exactly one scalar renderable value on the stack: nil, bool, number, or string.
